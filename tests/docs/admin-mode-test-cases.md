## 1. 目的与范围

本文档验证应用内管理员模式的密码弹窗、身份校验、界面状态、日志记录和会话生命周期。

这里的“管理员模式”是应用内部状态，不是 Windows 的“以管理员身份运行”，当前实现不会触发 UAC，也不提升进程或操作系统权限。

本轮纳入范围：

- 默认状态与入口展示。
- 密码弹窗的打开、提交、取消及键盘操作。
- 正确、错误和边界密码输入。
- 启用后的状态展示、重复操作与进程重启行为。
- 状态栏、内存日志、文件日志和设置文件中的敏感信息检查。
- 常用分辨率、缩放比例及托盘恢复场景。

暂不作为通过/失败判定的范围：

- 管理员模式具体解锁哪些页面、按钮或配置操作。当前代码未将 `AdminModeEnabled` 绑定到任何业务权限。
- 密码配置、修改、找回、过期和账户体系。当前实现只接受代码中固定的会话密码。
- Windows 用户组、UAC、文件 ACL 等操作系统权限。

## 2. 当前验收基线

以下内容来自当前实现，是本轮回归测试的明确预期：

| 项目 | 当前预期 |
| --- | --- |
| 初始状态 | 每次新进程启动时管理员模式为未启用 |
| 状态文案 | 未启用时显示“未启用”，启用后显示“已启用” |
| 有效密码 | `admin` |
| 比较规则 | 区分大小写，不自动去除首尾空白，必须完全匹配 |
| 失败行为 | 模式保持未启用，弹窗保持打开，清空密码框并提示“密码错误，请重新输入。” |
| 成功行为 | 模式变为已启用，关闭弹窗，清空密码框，并更新状态与日志 |
| 有效期 | 仅当前应用进程有效，不写入 `settings.json` |
| 退出管理员模式 | 已启用时再次单击开关，无需输入密码即可退出 |
| 已启用后再次单击 | 模式变为未启用，不显示密码弹窗，并更新状态与日志 |

## 3. 测试环境与前置条件

1. 使用 Windows 10 或 Windows 11，安装 .NET 8 Desktop Runtime/SDK。
2. 执行 `dotnet build DiagnosticFlashTool.slnx -c Debug`，使用本次构建产物测试。
3. 测试前备份 `%LocalAppData%\DiagnosticFlashTool\settings.json` 和现有日志；不得使用生产配置或生产 ECU 数据。
4. 除非用例明确要求复用会话，每个用例均完全退出进程后重新启动应用。
5. 日志验证时将日志页面的级别、时间范围和搜索条件恢复为“全部”或空值。
6. 测试过程中无需连接真实 CAN 设备；管理员模式本身应与 CAN 连接状态无关。

## 5. 功能与交互用例

| 用例 ID | 优先级 | 场景与步骤 | 预期结果 |
| --- | --- | --- | --- |
| ADM-UI-001 | P0 | 启动新进程，进入“系统设置”页面。 | “管理模式”开关为关闭；状态显示“未启用”；密码弹窗不可见。 |
| ADM-UI-002 | P0 | 在未启用状态单击“管理模式”开关。 | 显示遮罩与密码弹窗；标题为“启动管理员模式”；提示为“请输入管理员密码，本次启动内有效。”；密码框为空；按钮从左到右为带盾牌图标的“启动”和带关闭图标的“取消”；背景开关仍反映未启用状态。 |
| ADM-UI-003 | P1 | 在密码框输入任意字符并观察显示。 | 输入内容以掩码字符显示，不以明文显示；输入值可由提交操作正常读取。 |
| ADM-UI-004 | P0 | 打开弹窗，输入任意密码，单击“取消”；再次打开弹窗。 | 首次取消后弹窗关闭且模式仍未启用；不改变取消前的全局状态、不新增认证日志；再次打开时密码框为空且恢复初始提示。 |
| ADM-UI-005 | P1 | 打开弹窗，输入任意密码，在密码框内按 `Escape`；再次打开弹窗。 | 行为与单击“取消”一致，密码不会保留。 |
| ADM-UI-006 | P1 | 打开弹窗后尝试单击、滚动或用键盘操作遮罩后的页面控件。 | 弹窗显示期间背景页面不可操作，不应误改任何设置。 |
| ADM-UI-007 | P2 | 分别在 100%、125%、150% 缩放以及窗口最小支持尺寸下打开弹窗。 | 开关、状态、标题、提示、密码框和两个按钮无重叠、截断或溢出；弹窗位于可见区域。 |
| ADM-AUTH-001 | P0 | 打开弹窗，不输入内容，单击“启动”。 | 校验失败；模式保持未启用；弹窗不关闭；密码框为空；提示变为“密码错误，请重新输入。”。 |
| ADM-AUTH-002 | P0 | 输入 TD-WRONG-01，单击“启动”。 | 与 ADM-AUTH-001 的失败结果一致。 |
| ADM-AUTH-003 | P0 | 分别输入 TD-CASE-01 和 TD-SPACE-01，每次提交后重新输入下一组数据。 | 所有输入均校验失败，证明比较区分大小写且不自动修剪空白；每次失败后密码框均被清空。 |
| ADM-AUTH-004 | P1 | 分别输入 TD-UNICODE-01、TD-SPECIAL-01 和 TD-LONG-01 并提交。 | 应用无崩溃、卡死或明显延迟；输入均校验失败；错误提示及清空行为一致；日志中不出现输入内容。 |
| ADM-AUTH-005 | P0 | 输入 TD-VALID-01，单击“启动”。 | 校验成功；弹窗关闭；密码框绑定值被清空；开关变为开启；状态显示“已启用”。 |
| ADM-AUTH-006 | P0 | 新进程中打开弹窗，输入 TD-VALID-01，在密码框内按 `Enter`。 | 行为与 ADM-AUTH-005 一致，只执行一次提交，不产生重复日志。 |
| ADM-AUTH-007 | P0 | 先提交一次错误密码，确认错误提示后输入 TD-VALID-01 再提交。 | 第二次提交成功；先前失败不会阻止本次认证；错误提示随弹窗关闭而不可见。 |
| ADM-AUTH-008 | P1 | 连续提交 10 次错误密码，再提交 TD-VALID-01。 | 按当前实现，无锁定或延迟，第 11 次正确输入仍可启用；应用保持响应。该结果不代表推荐的安全策略。 |
| ADM-STATE-001 | P0 | 在密码弹窗打开期间及一次失败提交后观察页面开关和状态。 | 开关始终为关闭，状态始终为“未启用”，不得仅因用户单击 ToggleButton 而短暂保持为开启。 |
| ADM-STATE-002 | P0 | 成功启用后再次单击已开启的开关。 | 不显示密码弹窗；开关变为关闭；状态显示“未启用”；管理员模式退出；再次单击时重新显示密码弹窗。 |
| ADM-STATE-003 | P0 | 成功启用后在各现有页面间切换，再返回系统设置。 | 同一进程内状态保持“已启用”，不会因导航切换而丢失。 |
| ADM-STATE-004 | P1 | 开启“后台运行”，成功启用管理员模式；将主窗口关闭到托盘并恢复。 | 进程未退出时管理员状态仍为“已启用”。 |
| ADM-STATE-005 | P0 | 成功启用后完全退出应用进程，再重新启动并进入系统设置。 | 管理员模式恢复为“未启用”，必须重新输入密码。 |
| ADM-STATE-006 | P1 | 分别在 CAN 未连接、Mock 已连接和刷写未运行状态进入管理员认证。 | 认证结果只由密码决定，不依赖 CAN 设备或项目选择。刷写执行中是否允许认证需另行确认，不在本轮破坏性测试中执行。 |

## 9. 已识别风险与待决策项

| 编号 | 风险或问题 | 影响 |
| --- | --- | --- |
| R-ADM-001 | 管理员状态当前没有保护任何页面或业务命令 | 若功能目标是访问控制，则目前可被完全绕过 |
| R-ADM-002 | 有效密码以明文常量硬编码在客户端 | 反编译或查看源码即可获得密码，不适合作为安全边界 |
| R-ADM-003 | 错误密码没有次数限制、退避或锁定 | 可无限尝试密码 |
| R-ADM-004 | 支持手动退出，但没有空闲超时或锁屏失效机制 | 用户未主动退出时，权限状态会持续到进程结束 |
| R-ADM-005 | 界面同时使用“管理模式”和“管理员模式” | 用户认知及测试术语不一致 |
| R-ADM-006 | 认证日志文本与日志级别分类关键词不匹配 | 成功和失败事件可能都显示为中性级别，影响审计筛选 |

发布前至少需要明确 R-ADM-001 的权限边界和 R-ADM-002 的密码策略；否则管理员模式只能视为界面状态功能，不能视为可靠的授权控制。
