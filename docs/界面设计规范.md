# UI 设计规范

- 版本：2.0
- 最近修订：2026-10-14
- 适用项目：`DiagnosticFlashTool.App`
- 精确值来源：`src/DiagnosticFlashTool.App/Styles/`、复用控件和当前页面源码

本文规定页面、控件、对话框、导航和样式的设计与实现流程。它是可见 UI 改动的强制前置规范，目标是延续当前 WPF/MVVM 界面体系，并让设计决策可复用、可检查、可追溯。

## 1. 适用范围与事实来源

以下改动必须遵循本文：

- 新建或修改 `Views/**/*.xaml`、`MainWindow.xaml` 及相关代码隐藏。
- 新建或修改 `Styles/**/*.xaml`、应用资源、图标、主题颜色或控件模板。
- 修改导航、对话框、可见文案、状态反馈、布局尺寸或交互行为。
- ViewModel 改动会改变页面结构、控件状态或用户操作流程。

事实来源按职责分层，不使用单一优先级混合判断：

| 层级 | 负责内容 | 事实来源 |
|---|---|---|
| 任务要求 | 本次交付范围、业务目标、明确例外 | 用户对当前任务的明确要求 |
| 规范规则 | 模板选择、资源准入、交互语义、状态与验收 | 本文正文 |
| 精确实现 | 颜色、尺寸、间距、模板属性和控件状态 | 当前 `Styles/`、`Views/Controls/` 与相关 XAML |

发生冲突时，先判断冲突属于哪个层级。业务页面不得复制历史统计或示例数值；应引用资源字典或复用控件。文档与源码不一致时，应修正文档或明确记录有意偏离，不得再创建一套近似实现。

## 2. 修改前的强制流程

AI 或开发者在编辑可见 UI 前必须完成以下步骤：

1. 从第 4 节选择最接近的参考模板；页面类型是参考目录，不是封闭枚举，可组合多个既有模式。
2. 阅读本次会使用的资源字典，并检查至少一个最接近的现有页面及目标页面的相邻布局。
3. 在工作进度中先给出简短设计说明，包括页面类型、参考页面、复用资源、关键交互与状态、必要的模板偏离。
4. 明确绑定、命令和状态归属。业务状态放 ViewModel，代码隐藏仅承载必须依赖视图对象的交互。
5. 判断新视觉或布局模式是否会在两个及以上位置使用，再决定放入 `Styles/`、`Views/Controls/` 或页面局部资源。
6. 实现后按第 11 节执行验收。

推荐的设计说明格式：

```text
页面类型：表单设置页
参考页面：SystemSettingsView
复用资源：PageRootGridStyle、HeaderedCard.Form、Card.FormRowsContent、FieldLabelStyle
关键交互与状态：加载、编辑、保存中、校验失败
模板偏离：无；或说明偏离原因
```

局部视觉修复可以缩短说明，但仍需核对目标控件的父级布局、相邻区域与既有样式。

### 2.1 存量偏差处理

- 现有页面与规范不一致不代表新代码可以继续复制该偏差。
- 本次范围内直接受影响且可安全修复的偏差，应一并修复并说明。
- 超出本次范围、可能改变交互或需要全局迁移的偏差，只登记为后续任务，不做顺手重构。
- 候选死资源、重复资源或样式变体在完成资源依赖分析前不得删除、重命名或合并。
- 有意保留的偏离必须说明业务原因、影响范围和验证方式。

## 3. 资源入口与准入

`Styles/AppStyles.xaml` 是应用样式合并入口。按职责查找和新增资源：

| 职责 | 文件 |
|---|---|
| 颜色令牌和语义画刷 | `Styles/Colors.xaml`、`Styles/Brushes.xaml` |
| 字体和文本层级 | `Styles/Typography.xaml` |
| 按钮与图标 | `Styles/Controls/ButtonStyles.xaml` |
| 输入框、下拉框、开关、进度条 | `Styles/Controls/InputStyles.xaml` |
| 表格 | `Styles/Controls/DataGridStyles.xaml` |
| 页面页头 | `Styles/Controls/PageHeaderStyles.xaml` |
| 卡片和字段 | `Styles/Layout/CardStyles.xaml` |
| 带标题卡片 | `Styles/Layout/HeaderedCardStyles.xaml` |
| 页面骨架与间距令牌 | `Styles/Layout/PageStyles.xaml` |
| Shell 导航与内容区 | `Styles/Shell/ShellStyles.xaml` |
| 业务状态和日志 | `Styles/Domain/StatusStyles.xaml`、`Styles/Domain/LogStyles.xaml` |

资源准入规则：

- 优先组合已有资源和复用控件，不在业务页面复制通用 `ControlTemplate`。
- 页面独有且不具复用价值的业务布局可放页面局部资源，不应无条件提升为全局样式。
- 同一视觉或布局模式确认会在两个及以上位置使用时，放入职责最接近的资源字典或复用控件。
- 业务页面不得硬编码十六进制颜色、重复阴影、圆角或已有控件模板。
- 新增全局资源应使用能表达职责和语义的名称，不以单个页面名或临时位置命名。
- 删除资源前必须检查静态引用、`BasedOn`、模板内部引用、动态资源和代码访问；单纯正则零命中不足以证明可删除。

### 3.1 语义到资源映射

| 语义 | 推荐公开入口 | 说明 |
|---|---|---|
| 页面根布局 | `PageRootGridStyle` | 页面外边距由资源统一提供 |
| 页面页头 | `PageHeader.Standard` | 与标准页头行和间隔配套使用 |
| 页头帮助入口 | `PageHelpDocumentButton.Standard` | 业务页面唯一推荐入口；`Button.HelpDocument` 仅供复用控件内部实现 |
| 无标题普通卡片 | `Card.Standard`、`Card.Compact`、`Card.Form` | 按内容密度和语义选择 |
| 带标题表单 | `HeaderedCard.Form` 系列 | 表单、设置、路径和选项 |
| 带标题面板 | `HeaderedCard.Panel` 系列 | 状态、进度、日志和诊断区域 |
| 带标题数据区 | `HeaderedCard.Data` 系列 | 表格和列表 |
| 表单内容布局 | `CardContentPanel` + `Card.FormRowsContent` | 统一行间距与末行处理 |
| 路径显示和操作 | `PathDisplayBorderStyle`、`PathDisplayTextStyle`、`Button.PathAction` | 不自建近似路径控件 |
| Shell 内模态 | `DialogOverlayStyle`、`DialogPanelStyle`、`Button.Dialog*` | 遮罩、面板和操作按钮配套使用 |

## 4. 参考模板目录

页面类型表用于寻找起点，不是封闭枚举。选择最接近用户工作流的页面，而不是只比较视觉相似度。

| 页面类型 | 首选参考 | 适用场景 |
|---|---|---|
| 简单只读列表 | `AlgorithmConfigView.xaml` | 单卡片、只读表格、少量页头元信息 |
| 列表加侧边编辑 | `ProjectConfigView.xaml` | 主表格、选择项编辑、新增、保存和删除工作流 |
| 多组表单设置 | `SystemSettingsView.xaml` | 可滚动设置卡、路径操作、开关和说明 |
| 运行监控/状态工作台 | `FirmwareFlashView.xaml` | 状态卡、设备操作、配置摘要和进度反馈 |
| 复杂流程编辑 | `FlowConfigView.xaml` | 工具区、可编辑表格、排序/拖放和校验结果 |
| 日志与过滤工具 | `SystemLogView.xaml` | 工具栏、过滤条件和日志内容区 |
| 空状态或待接入列表 | `FlashHistoryView.xaml` | 暂无数据、说明和后续列表承载区 |
| 诊断工具工作台 | `DeveloperOptionsView.xaml` | 多区域操作、消息发送、实时表格和进度 |
| Shell 内确认/输入 | `SystemSettingsView.xaml` 管理员密码遮罩 | 不离开主窗口的短流程模态交互 |
| 独立模态窗口 | `UnsavedChangesDialog.xaml` | 需要独立 Window 生命周期的确认与分支选择 |

没有单一合适模板时，应组合标准页面骨架、已有卡片和控件；只有形成可复用的新模式时才新增全局模板。

## 5. 标准页面骨架

普通 Shell 页面从以下结构开始，再按业务增加主体行列：

```xml
<Grid Style="{StaticResource PageRootGridStyle}">
    <Grid.RowDefinitions>
        <RowDefinition Style="{StaticResource PageHeaderRowStyle}" />
        <RowDefinition Style="{StaticResource PageHeaderGapRowStyle}" />
        <RowDefinition Height="*" />
    </Grid.RowDefinitions>

    <controls:PageHeader Grid.Row="0"
                         Style="{StaticResource PageHeader.Standard}"
                         Breadcrumb="页面分组"
                         Title="页面标题">
        <controls:PageHeader.Actions>
            <controls:PageHelpDocumentButton Style="{StaticResource PageHelpDocumentButton.Standard}" />
        </controls:PageHeader.Actions>
    </controls:PageHeader>

    <Border Grid.Row="2" Style="{StaticResource Card.Compact}">
        <!-- 页面主体 -->
    </Border>
</Grid>
```

骨架规则：

- 根布局、页头行和页头间隔直接复用全局资源；精确值从 `PageStyles.xaml` 和 `PageHeaderStyles.xaml` 读取。
- `PageHeader` 显式使用 `PageHeader.Standard`；左侧显示路径导航，右侧只放帮助入口和必要元信息。
- 多区块间距优先使用 `PageSectionGapRowStyle`、`PageColumnGapStyle`、`PageCardBottomGap` 等资源。
- 普通内容卡片复用 `CardContentPadding`、`CardHorizontalContentPadding`、`CardHeaderContentPadding`、`HeaderedCardBodyPadding` 或包含这些令牌的现有样式。
- 内容超出可用高度时，只在主体内容层使用纵向 `ScrollViewer`，固定页头和 Shell 不随内容滚动。
- `Auto` 用于由内容决定的尺寸，`*` 用于分配剩余空间。固定宽高只用于稳定工具栏、状态卡、协议字段等确有格式要求的区域。
- 避免卡片嵌套卡片。卡片内部使用标题、Grid、分隔线或 `SettingGroupPanelStyle` 分组。

### 5.1 `HeaderedCard` 语义

- `HeaderedCard.Actions` 是标题操作区的内容属性；存在操作内容不等于必须使用名称带 `.Actions` 的样式。
- 标准 `Form`、`Panel`、`Data` 变体用于无操作、文本元信息或单个图标操作。
- 名称带 `.Actions` 的变体用于多个标准工具栏按钮，需要更高标题栏来保持垂直间距的场景。
- 单个关闭图标可以继续使用标准标题栏，不应为了存在操作区自动切换到 `.Actions`。
- `.Lead` 只表达与后续卡片的底部间距，不改变内容语义。
- `Panel.Centered` 仅用于固定或稳定高度、单行进度或短状态内容在剩余区域垂直居中；动态表单、日志和数据列表不得使用。
- 标题高度、标题到正文间距和正文边距由 `HeaderedCard.Base` 集中管理。页面不得用正文顶部 `Margin` 补偿标题间距，也不得设置不会参与模板的继承 `Padding`。

## 6. 常用内容模板

### 6.1 表单与设置

- 带标题的表单卡片优先使用 `HeaderedCard.Form`；需要卡片下间距时使用 `.Lead`。
- 标题操作放入 `HeaderedCard.Actions`，不得在内容区重复搭建标题行。
- 表单内容优先使用 `CardContentPanel` + `Card.FormRowsContent`；字段标签使用 `FieldLabelStyle`，标签列优先使用 `FormLabelColumnStyle`。
- 同一卡片中的标签列宽保持一致。输入内容需要占满余量时使用 `Width="Auto"` 和 `HorizontalAlignment="Stretch"`。
- 设置项说明使用 `SettingAssistTextStyle`，不要用醒目标题代替辅助说明。

### 6.2 数据列表与编辑区

- 带标题的数据区使用 `HeaderedCard.Data` 系列，内容区沿用统一的 `HeaderedCardBodyPadding`。
- 表格沿用隐式 DataGrid 样式或 `DataGrid.Base`，只在业务需要时定义列、单元格模板和列宽。
- 长表格和长列表默认设置 `ScrollViewer.VerticalScrollBarVisibility="Hidden"`，保留鼠标滚轮、触控板和键盘滚动；不得用会禁用滚动的 `Disabled` 代替。
- 需要拖动滑块快速定位、显式滚动提示或主要输入方式不便滚轮滚动时，可以保留可见滚动条，并说明原因。
- 主信息列可使用 `*`；标识、时间、状态等格式稳定的列使用有依据的固定宽度。
- 表格操作放在卡片标题行或紧邻表格的工具栏，使用 `Button.ToolBar`。
- 侧边编辑区必须有明确的打开、保存、取消和必要的删除路径；显示状态由 ViewModel 控制。
- 空数据不能只留下空白表格，应提供简洁空状态和可执行的下一步。

### 6.3 运行监控与诊断工作台

- 状态面板、日志和诊断区域使用 `HeaderedCard.Panel`；固定高度的短进度或状态区域使用 `Panel.Centered`。
- 优先展示连接状态、当前配置、主操作、进度和结果，不增加与诊断工具无关的装饰区域。
- 状态使用 `Status*Style`、图标和文字共同表达，不能只依赖颜色。
- 长时间操作显示忙碌或进度状态，并禁用会造成重复执行或状态冲突的操作。
- 日志、报文和协议字段采用稳定尺寸；动态内容使用裁切、省略、滚动或等宽字体，不能推动工具栏和主操作跳动。

## 7. 对话框与模态窗口

### 7.1 Shell 内遮罩

- 复用 `DialogOverlayStyle`、`DialogPanelStyle`、`Button.DialogPrimary` 和 `Button.DialogSecondary`。
- 遮罩覆盖所属交互区域并具有明确层级；显示状态由 ViewModel 控制。
- 打开后聚焦首个合理控件，关闭后恢复到触发控件或其他合理位置。
- 支持适用的 Enter/Escape 键，并覆盖确认、取消、关闭和命令失败路径。

### 7.2 独立模态窗口

- 以 `UnsavedChangesDialog.xaml` 作为独立 Window 参考，复用应用画刷、卡片和对话框按钮资源。
- 明确所有关闭路径的结果，包括标题栏关闭、取消、确认和多分支选择。
- 由宿主设置 Owner，并避免创建第二套主题、阴影和按钮语义。
- 固定尺寸只用于内容稳定且禁止调整大小的短确认窗口；内容可能增长时使用最小尺寸和内容自适应。

默认、取消和危险操作必须在语义与视觉上区分。危险操作使用明确确认文案，不得伪装为普通主操作。

## 8. 控件和视觉规则

- 普通、主操作、危险、工具栏、纯图标、路径和对话框按钮分别选择现有 `Button.*` 样式。
- 有对应 MaterialDesign `PackIcon` 时使用现有图标库。图标加文字按钮使用 `Button.InlineContent`、`Button.PackIcon.Current` 和 `Button.IconLabel`。
- 纯图标按钮必须提供 `ToolTip`；相同作用在不同页面使用相同图标和文案。
- 文本输入、密码、下拉、开关和进度条复用 `SoftTextBoxStyle`、`SoftPasswordBoxStyle`、`StandardComboBoxStyle`、`SoftSwitchStyle`、`SoftProgressBarStyle`。
- 颜色只通过语义画刷资源引用，文字遵循 `Typography.xaml` 的层级。
- UI 文案使用中文；协议名、标准名、文件格式和必要字段标识可保留英文。操作文案使用清晰动词。
- 长路径、日志和动态文本使用 `TextTrimming`、换行、滚动或完整内容 `ToolTip`，不得覆盖相邻控件。

## 9. 交互、状态与 MVVM

- 用户操作通过命令绑定进入 ViewModel。同步操作用 `RelayCommand`，异步操作用 `AsyncRelayCommand` 和 `CancellationToken`。
- 不得在 UI 线程执行文件解析、设备通信、刷写或大批量数据处理。
- 代码隐藏只处理拖放、焦点、窗口、滚动和控件专属事件；业务判断、数据修改和流程编排放入 ViewModel/Core。
- 每个页面按实际工作流检查初始、正常、无数据、加载/执行中、禁用、校验失败、操作失败、取消和完成状态。
- 状态列表是适用性检查表，不要求每个页面机械实现全部状态，但不得遗漏适用的失败路径和重复提交防护。
- 命令执行期间保持布局稳定；状态文字、进度值和按钮文案变化不得导致关键控件跳位或遮挡。
- 错误反馈说明发生了什么以及用户可以采取的下一步，不向用户显示无上下文的异常堆栈。

## 10. 可用性与可访问性

- 以 `MainWindow` 的当前最小尺寸为下限检查页面，不得依赖默认启动尺寸才可使用。
- 工具栏和表单在空间不足时通过合理列布局、换行、滚动或省略处理，不允许相互覆盖。
- 数字、CAN ID、地址、进度和状态区域保持稳定宽度，数据变化不应重排整页。
- 可点击区域需要明确的悬停、按下、禁用和键盘焦点状态，优先由共享样式提供。
- 状态和错误不能仅通过颜色传递，应同时使用文字、图标或状态点。
- 交互顺序应符合视觉顺序；对话框和复杂表单应验证 Tab、Shift+Tab、Enter 和 Escape。
- 纯图标操作提供可理解的 `ToolTip`；输入控件必须有邻近标签或可识别的说明。
- 文本缩放、长中文文案和动态路径不得被无提示裁切；必要时提供换行、省略和完整内容提示。
- 不添加纯装饰渐变、光斑、营销式悬浮卡片或与诊断工具场景无关的视觉元素。

## 11. 新页面接入与完成验收

新页面除创建 `Views/<Name>View.xaml` 和代码隐藏外，还必须：

- 在 `MainWindow.xaml` 的 Shell 导航和 `TabControl` 中按同一顺序接入。
- 更新 `MainViewModel.SelectedShellIndex` 相关命令和索引分支。
- 使页面标题、帮助入口、权限和可见性与导航一致。
- 复用现有 ViewModel 手动装配方式，不引入 DI 容器。
- 将真正可复用的控件或资源放入 `Views/Controls/` 或对应 `Styles/` 分类，并更新本文资源索引。

导航索引是位置契约。插入或删除页面时必须检查所有硬编码索引、命令跳转和上下文文案。

提交可见 UI 改动前逐项确认：

- 已说明页面类型、参考页面、复用资源、关键交互与状态、模板偏离。
- 页面使用标准根骨架、页头和合适的内容模板。
- 已检查常规、空数据、忙碌/禁用、错误以及其他适用状态。
- 已检查异步防重入、取消、失败反馈和布局稳定性。
- 已在 `MainWindow` 最小尺寸下确认无裁切、遮挡或文本溢出。
- 已检查键盘焦点、Tab 顺序、Enter/Escape、纯图标提示和非颜色状态表达。
- 新页面已核对导航顺序、Tab 顺序、`SelectedShellIndex` 和上下文文案。
- 已执行 `dotnet build DiagnosticFlashTool.slnx -c Debug`。
- 已尽可能运行应用检查；无法执行的运行时检查在交付说明中明确列出。

仅修改 Markdown 文档且未改动 XAML/C# 时，可以不执行 Debug 构建，但必须完成链接、术语和格式检查。

## 12. 自动检查边界

适合先实施的低误报检查：

- 业务页面新增硬编码十六进制颜色。
- Shell 页面缺少标准根布局、页头样式或公开帮助按钮入口。
- 长表格/列表将垂直滚动设置为 `Disabled`。
- 新页面未接入 Shell 导航或 `TabControl`，或顺序不一致。
- 文档链接失效、Markdown 尾随空白和重复标题。

以下检查不能只靠简单正则作最终判定：

- 样式、画刷或控件资源是否为死资源。
- `BasedOn`、`StaticResource`、`DynamicResource` 和模板内部依赖是否完整。
- 两个资源是否语义重复、是否应合并。
- 页面状态是否覆盖完整、焦点顺序是否合理、最小窗口是否裁切。

这类问题需要资源依赖图、XAML 解析或运行时人工复核。自动检查结果应作为线索，不直接触发删除或大范围重构。

## 13. 术语

| 术语 | 定义 |
|---|---|
| Shell 页面 | 挂载在 `MainWindow` 导航和主 `TabControl` 中的业务页面 |
| 页面骨架 | 页面根布局、页头、页头间隔和主体区域的标准结构 |
| 公开资源入口 | 业务页面应直接引用的稳定样式或复用控件资源 |
| 内部实现资源 | 仅供复用控件或模板内部使用，不向业务页面推荐的资源 |
| 存量偏差 | 当前实现与规范不一致、但尚未在本次范围修复的内容 |
| `HeaderedCard.Actions` | `HeaderedCard` 标题栏右侧的内容属性 |
| `.Actions` 变体 | 为多个标题栏操作提供更高标题区的样式后缀 |
| `.Lead` 变体 | 为后续卡片预留统一底部间距的样式后缀 |
