# UI 设计规范

- 版本：4.4
- 最近修订：2026-11-24
- 适用项目：`DiagnosticFlashTool.App`
- 精确值来源：`src/DiagnosticFlashTool.App/Styles/`、复用控件和当前页面源码

本文规定页面、控件、对话框、导航和样式的设计与实现流程。它是可见 UI 改动的强制前置规范，目标是在 .NET 10 WPF 官方 Fluent 主题上延续当前 WPF/MVVM 界面体系，并让设计决策可复用、可检查、可追溯。

## 1. 适用范围与事实来源

以下改动必须遵循本文：

- 新建或修改 `Views/**/*.xaml`、`MainWindow.xaml` 及相关代码隐藏。
- 新建或修改 `Styles/**/*.xaml`、应用资源、图标、主题颜色或控件模板。
- 修改导航、对话框、可见文案、状态反馈、布局尺寸或交互行为。
- ViewModel 改动会改变页面结构、控件状态或用户操作流程。

事实来源按职责分层，不使用单一优先级混合判断：

| 层级 | 负责内容 | 事实来源 |
|---|---|---|
| 任务要求 | 本次交付范围、业务目标、明确例外 | 用户对当前任务的明确要求 |
| 规范规则 | 模板选择、资源准入、交互语义、状态与验收 | 本文正文 |
| 精确实现 | 颜色、尺寸、间距、模板属性和控件状态 | 当前 `Styles/`、`Views/Controls/` 与相关 XAML |

发生冲突时，先判断冲突属于哪个层级。业务页面不得复制历史统计或示例数值；应引用资源字典或复用控件。文档与源码不一致时，应修正文档或明确记录有意偏离，不得再创建一套近似实现。

## 2. 修改前的强制流程

AI 或开发者在编辑可见 UI 前必须完成以下步骤：

1. 从第 4 节选择最接近的参考模板；页面类型是参考目录，不是封闭枚举，可组合多个既有模式。
2. 阅读本次会使用的资源字典，并检查至少一个最接近的现有页面及目标页面的相邻布局。
3. 在工作进度中先给出简短设计说明，包括页面类型、参考页面、复用资源、关键交互与状态、必要的模板偏离。
4. 明确绑定、命令和状态归属。业务状态放 ViewModel，代码隐藏仅承载必须依赖视图对象的交互。
5. 判断新视觉或布局模式是否会在两个及以上位置使用，再决定放入 `Styles/`、`Views/Controls/` 或页面局部资源。
6. 实现后按第 11 节执行验收。

推荐的设计说明格式：

```text
页面类型：表单设置页
参考页面：SystemSettingsView
复用资源：PageRootGridStyle、HeaderedCard.Form、Card.FormRowsContent、FieldLabelStyle
关键交互与状态：加载、编辑、保存中、校验失败
模板偏离：无；或说明偏离原因
```

局部视觉修复可以缩短说明，但仍需核对目标控件的父级布局、相邻区域与既有样式。

### 2.1 存量偏差处理

- 现有页面与规范不一致不代表新代码可以继续复制该偏差。
- 本次范围内直接受影响且可安全修复的偏差，应一并修复并说明。
- 超出本次范围、可能改变交互或需要全局迁移的偏差，只登记为后续任务，不做顺手重构。
- 候选死资源、重复资源或样式变体在完成资源依赖分析前不得删除、重命名或合并。
- 有意保留的偏离必须说明业务原因、影响范围和验证方式。

## 3. 资源入口与准入

`Styles/AppStyles.xaml` 是应用样式合并入口。按职责查找和新增资源：

| 职责 | 文件 |
|---|---|
| 官方 Fluent 主题、系统强调色与品牌色桥接 | `Styles/FluentTheme.xaml` |
| 颜色令牌和语义画刷 | `Styles/Colors.xaml`、`Styles/Brushes.xaml` |
| 字体和文本层级 | `Styles/Typography.xaml` |
| 按钮与图标 | `Styles/Controls/ButtonStyles.xaml` |
| 系统符号图标与按钮状态资源桥接 | `Views/Controls/FluentIcon.cs`、`Views/Controls/FluentButtonAssist.cs` |
| 输入框、下拉框、开关、进度条 | `Styles/Controls/InputStyles.xaml` |
| 表格 | `Styles/Controls/DataGridStyles.xaml` |
| 页面页头 | `Styles/Controls/PageHeaderStyles.xaml` |
| 卡片和字段 | `Styles/Layout/CardStyles.xaml` |
| 带标题卡片 | `Styles/Layout/HeaderedCardStyles.xaml` |
| 页面骨架与间距令牌 | `Styles/Layout/PageStyles.xaml` |
| Shell 导航与内容区 | `Styles/Shell/ShellStyles.xaml` |
| 业务状态和日志 | `Styles/Domain/StatusStyles.xaml`、`Styles/Domain/LogStyles.xaml` |

资源准入规则：

- 应用级主题入口使用 `Application.ThemeMode`；当前交付固定为 `Light`，未经完整暗色适配和页面验收不得切换为 `System` 或 `Dark`。
- 官方 Fluent 负责标准控件的基础外观、焦点和系统交互语义；业务页面继续通过现有 `Button.*`、`HeaderedCard.*`、`PageHeader.*` 和 `Status*Style` 等稳定语义键引用样式。
- `FluentTheme.xaml` 负责把 WPF 系统强调色映射到稳定产品品牌色，现场工具不得随操作系统个性化颜色改变主操作、选中和焦点语义。
- 图标统一使用共享 `FluentIcon`，优先使用系统 Segoe Fluent Icons 字体，在未安装该字体的 Windows 环境回退到 Segoe MDL2 Assets；只采用两套字体共有的字形。不重新引入 MaterialDesign 控件主题、颜色体系或图标依赖。
- 危险和断开连接按钮通过 `FluentButtonAssist.StateResources` 为官方模板提供局部状态画刷；不得复制按钮模板解决悬停、按下色被官方模板覆盖的问题。
- 优先组合已有资源和复用控件，不在业务页面复制通用 `ControlTemplate`。
- 页面独有且不具复用价值的业务布局可放页面局部资源，不应无条件提升为全局样式。
- 同一视觉或布局模式确认会在两个及以上位置使用时，放入职责最接近的资源字典或复用控件。
- 业务页面不得硬编码十六进制颜色、重复阴影、圆角或已有控件模板。
- 新增全局资源应使用能表达职责和语义的名称，不以单个页面名或临时位置命名。
- 删除资源前必须检查静态引用、`BasedOn`、模板内部引用、动态资源和代码访问；单纯正则零命中不足以证明可删除。

## 5. 标准页面骨架

普通 Shell 页面从以下结构开始，再按业务增加主体行列；有必要元信息时再添加页头及其间隔行：

```xml
<Grid Style="{StaticResource PageRootGridStyle}">
    <Border Style="{StaticResource Card.Compact}">
        <!-- 页面主体 -->
    </Border>
</Grid>
```

骨架规则：

- 根布局、页头行和页头间隔直接复用全局资源；精确值从 `PageStyles.xaml` 和 `PageHeaderStyles.xaml` 读取。
- `PageHeader` 显式使用 `PageHeader.Standard`，仅承载必要元信息；无元信息时省略页头和对应间隔行，不保留空白占位。视图名称由 Shell 导航展示，页面顶部不再重复显示；帮助文档统一从 Shell「帮助」菜单进入。
- 间距与内边距只从 5.1 的令牌取值，页面不写数值，也不为对齐额外加 `Margin`。
- 内容超出可用高度时，只在主体内容层使用纵向 `ScrollViewer`，固定页头和 Shell 不随内容滚动。
- `Auto` 用于由内容决定的尺寸，`*` 用于分配剩余空间。固定宽高只用于稳定工具栏、状态卡、协议字段等确有格式要求的区域。
- 避免卡片嵌套卡片。卡片内部使用标题、Grid、分隔线或 `SettingGroupPanelStyle` 分组。

### 5.1 间距与留白（唯一规则）

页面外边距用于内容区四边，区块间距用于卡片和区块之间。卡片内部以开发者选项中「帧 ID」所在的工具条为基准。普通卡片、工具条卡片和带标题卡片的首行或内容区统一从卡片上沿下方 11 DIP 开始，包含 1 DIP 边框和 10 DIP 内边距。内容区左侧统一从边框内沿向右留 17 DIP。工具条首行和卡片标题行使用共享行高，文字在行内垂直居中。

所有没有标题的卡片都沿用帧 ID 工具条的上下间距：首行或唯一行取 `CardContentRowHeight`（32），由公开样式 `Card.ContentRow` 提供；单行卡片因此固定为 54 DIP（1 边框 + 10 + 32 + 10 + 1）。内容不足 32 DIP 时在该行内垂直居中，顶部和底部留白保持各 10 DIP，不靠 `Margin` 或额外内边距补贴。带标题卡片、`DialogPanelStyle` 对话框面板和整块填充的表格卡不属于本规则。

| 场景 | 令牌（来源） | 当前值 |
|---|---|---|
| 内容区到页面四边 | `PageRootGridStyle` → `PageMargin`（`Layout/PageStyles.xaml`） | 16,16,16,16 |
| 卡片、区块之间的行间距 | `PageSectionGapRowStyle` | 14 |
| 卡片、区块之间的列间距 | `PageColumnGapStyle` | 14 |
| 页头与首个内容区块之间 | `PageHeaderGapRowStyle` | 6 |
| 卡片与后续内容的附加底距 | `PageCardBottomGap`；样式后缀 `.Lead` | 0,0,0,14 |
| 页面卡片内边距 | `CardContentPadding`（`CardStyle`） | 17,10,12,10 |
| 带标题卡片的标题行上下留白 | `CardContentPadding.Top`（`HeaderedCard.Base`） | 各 10 |
| 工具条首行与卡片标题行的高度 | `CardContentRowHeight` | 32 |
| 无标题卡片首行或唯一行的高度 | `Card.ContentRow`（`CardContentRowHeight`） | 32 |
| 标题行左右内边距 | `CardHorizontalContentPadding` | 17,0,12,0 |
| 带标题卡片正文内边距 | `HeaderedCardBodyPadding` | 17,0,12,10 |
| 带标题数据卡片正文内边距 | `HeaderedCardDataBodyPadding`（`HeaderedCard.Data`） | 17,0,17,17 |
| 启用标题分隔线时，正文内边距 | `HeaderedCardDividedBodyPadding` | 17,12,12,12 |
| 表单行距与末行 | `CardContentPanel` + `Card.FormRowsContent` | 由控件统一，页面不设 |

- 调整整体节奏时只改对应令牌并同步本表；不得在页面或视图里写数值、叠加内层内边距，或用 `Margin` 补偿样式间距。
- 本表是间距规则的唯一位置，其他章节只引用本节。精确值以 `Styles/Layout/PageStyles.xaml`、`CardStyles.xaml`、`HeaderedCardStyles.xaml` 源码为准，文档与源码不一致时以源码为准。
- 数据卡片内的表格和列表是整块矩形，四边留白必须等宽：左右底统一取内容区左侧的 17 DIP，上边沿用 0，由标题行下方留白承担。其余卡片仍用 17,0,12,10 与非对称的标题行留白对齐。

### 5.2 `HeaderedCard` 语义

- `HeaderedCard.Actions` 是标题操作区的内容属性；存在操作内容不等于必须使用名称带 `.Actions` 的样式。
- 标准 `Form`、`Panel`、`Data` 变体用于无操作、文本元信息或单个图标操作。
- 名称带 `.Actions` 的变体用于多个标准工具栏按钮，只表达标题操作语义，标题栏高度与标准一致；不得通过增高标题栏制造标题偏移。
- `HeaderedCard.Base` 按 5.1 节的共享资源设置标题行高和上下留白，并使用 `CardHeaderTextStyle` 设置标题文字。表单、面板和数据卡片均继承此模板，标题与操作在同一行内垂直居中。标题分隔线位于标题行下方留白之后。
- 单个关闭图标可以继续使用标准标题栏，不应为了存在操作区自动切换到 `.Actions`。
- `.Lead` 只表达与后续卡片的底部间距，不改变内容语义。
- `Panel.Centered` 仅用于固定或稳定高度、单行进度或短状态内容在剩余区域垂直居中；动态表单、日志和数据列表不得使用。
- 标题高度、标题到正文间距和正文边距由 `HeaderedCard.Base` 集中管理。页面不得用正文顶部 `Margin` 补偿标题间距，也不得设置不会参与模板的继承 `Padding`。

## 6. 常用内容模板

### 6.1 表单与设置

- 带标题的表单卡片优先使用 `HeaderedCard.Form`；需要卡片下间距时使用 `.Lead`。
- 无标题卡片统一引用 `Card.Standard`、`Card.Compact` 或 `Card.Toolbar`，正文内边距由样式提供；页面不得自行设置卡片 `Padding`、叠加内层内边距，或直接引用内部 `CardStyle`；内边距取值见 5.1。
- 无标题卡片的首行或唯一行引用 `Card.ContentRow` 取帧 ID 工具条的行高；不要在页面里再写 `MinHeight`、`Margin` 或局部样式补位。
- 标题操作放入 `HeaderedCard.Actions`，不得在内容区重复搭建标题行。
- 表单内容优先使用 `CardContentPanel` + `Card.FormRowsContent`；字段标签使用 `FieldLabelStyle`，标签列优先使用 `FormLabelColumnStyle`。
- 同一卡片中的标签列宽保持一致。输入内容需要占满余量时使用 `Width="Auto"` 和 `HorizontalAlignment="Stretch"`。
- 设置项说明使用 `SettingAssistTextStyle`，不要用醒目标题代替辅助说明。

### 6.2 数据列表与编辑区

- 带标题的数据区使用 `HeaderedCard.Data` 系列，正文内边距取 `HeaderedCardDataBodyPadding`（17,0,17,17），表格四边留白与内容区左侧一致。
- 所有 DataGrid 表格必须直接沿用 `Styles/Controls/DataGridStyles.xaml` 中的全局隐式样式或已存在的公开命名样式；表头、行、单元格、选择态、边框、间距、字体和对齐方式均以全局样式为准。
- 业务页面不得新建 DataGrid、`DataGridColumnHeader`、`DataGridRow` 或 `DataGridCell` 样式，不得通过 `DataGrid.Resources`、`DataGrid.ColumnHeaderStyle`、页面资源或控件属性局部覆盖全局表格视觉与交互。
- 页面只允许按业务需要定义列、数据绑定、单元格内容模板、合理列宽及必要的业务状态触发；状态模板仍须复用现有语义画刷、字体和共享控件，不得借此重建表格基础样式。
- 若现有全局表格样式不能满足需求或需要优化，必须在修改任何 XAML 或资源字典前先向用户说明问题、影响范围和建议方案，并取得明确确认；未经确认不得新增、修改或替换全局表格样式，也不得以页面局部样式绕过。
- 长表格和长列表默认设置 `ScrollViewer.VerticalScrollBarVisibility="Hidden"`，保留鼠标滚轮、触控板和键盘滚动；不得用会禁用滚动的 `Disabled` 代替。
- 需要拖动滑块快速定位、显式滚动提示或主要输入方式不便滚轮滚动时，可以保留可见滚动条，并说明原因。
- 主信息列可使用 `*`；标识、时间、状态等格式稳定的列使用有依据的固定宽度。
- 表格操作放在卡片标题行或紧邻表格的工具栏，按操作语义使用 `Button.Normal` 或 `Button.Danger`。
- 侧边编辑区必须有明确的打开、保存、取消和必要的删除路径；显示状态由 ViewModel 控制。
- 空数据不能只留下空白表格，应提供简洁空状态和可执行的下一步。

### 6.3 运行监控与诊断工作台

- 状态面板、日志和诊断区域使用 `HeaderedCard.Panel`；固定高度的短进度或状态区域使用 `Panel.Centered`。
- 整页只有一个日志或状态区域时，视图名称由 Shell 导航或停靠面板标题展示，内容区使用 `Card.Compact`，状态、路径、条数等元信息放在内容区顶部或工具栏，不再叠加 `HeaderedCard.Panel` 标题行；只有同页出现多个区块时才使用带标题卡片。
- 优先展示连接状态、当前配置、主操作、进度和结果，不增加与诊断工具无关的装饰区域。
- 状态使用 `Status*Style`、图标和文字共同表达，不能只依赖颜色。
- 长时间操作显示忙碌或进度状态，并禁用会造成重复执行或状态冲突的操作。
- 日志、报文和协议字段采用稳定尺寸；动态内容使用裁切、省略、滚动或等宽字体，不能推动工具栏和主操作跳动。

## 7. 对话框与模态窗口

### 7.1 Shell 内遮罩

- 复用 `DialogOverlayStyle`、`DialogPanelStyle`；普通、确认和保存操作使用 `Button.Normal`，破坏性选择使用 `Button.Danger`。
- 遮罩覆盖所属交互区域并具有明确层级；显示状态由 ViewModel 控制。
- 打开后聚焦首个合理控件，关闭后恢复到触发控件或其他合理位置。
- 支持适用的 Enter/Escape 键，并覆盖确认、取消、关闭和命令失败路径。

### 7.2 独立模态窗口

- 以 `UnsavedChangesDialog.xaml` 作为独立 Window 参考，复用应用画刷、卡片和对话框按钮资源。
- 明确所有关闭路径的结果，包括标题栏关闭、取消、确认和多分支选择。
- 由宿主设置 Owner，并避免创建第二套主题、阴影和按钮语义。
- 固定尺寸只用于内容稳定且禁止调整大小的短确认窗口；内容可能增长时使用最小尺寸和内容自适应。

默认、取消和危险操作必须在语义与视觉上区分。危险操作使用明确确认文案，不得伪装为普通主操作。

## 8. 控件和视觉规则

- 全软件按钮只使用两个公开视觉样式：`Button.Normal` 与 `Button.Danger`。主操作和普通操作合并为普通按钮，页面不得新增第三种按钮视觉样式。
- 刷新、浏览、导出、取消、返回、保存、创建、连接、开始、发送和确认等非破坏性操作统一使用 `Button.Normal`；删除、清空、中止、断开连接和放弃等破坏性操作使用 `Button.Danger`。
- 普通按钮正常状态为透明背景和品牌蓝前景，悬停与按下使用浅蓝交互底色。
- 危险按钮正常状态为透明背景和危险红前景；悬停时使用危险红背景与白色前景，按下时使用深红背景与白色前景。
- 纯图标、窗口控制和紧凑下拉仍按以下强制判定顺序选择样式，仅在控件上设置宽度、高度、内边距和必要间距，不另建图标按钮视觉样式：先判断是否为窗口控制，再判断是否会直接执行破坏性业务操作，其余全部归为普通操作。
- 主窗口及独立窗口右上角的最小化、最大化、还原和关闭按钮属于同组窗口控制，必须统一使用 `Button.Normal`，保持相同尺寸、间距、前景色及悬停、按下状态。关闭按钮是窗口控制的明确例外，不得因“关闭”文案、叉号图标或位于右上角而使用危险红色样式。
- 关闭窗口、关闭面板、关闭提示、返回和取消等仅结束当前视图或交互、且不直接删除数据或放弃修改的操作使用 `Button.Normal`；若操作会直接删除数据、清空内容、中止任务或放弃未保存修改，则按实际业务影响使用 `Button.Danger`，必要时增加二次确认。
- 按钮分类以操作结果为准，不以按钮文案、图标形状、所在位置或历史样式为准。窗口关闭过程中即使需要拦截未保存修改并弹出确认，标题栏关闭按钮本身仍使用 `Button.Normal`，确认窗口中的“放弃修改”操作使用 `Button.Danger`。
- 业务所需的宽度、最小宽度、边距和显隐可在控件上设置，但不得通过页面局部 `Style` 或新增全局按钮样式改变颜色、背景、字体、图标尺寸及悬停、按下、禁用状态。
- 图标使用 `FluentIcon` 和已有 `FluentIconKind`；图标加文字按钮使用 `Button.InlineContent`、`Button.Glyph.Current` 和 `Button.IconLabel`。`Button.Glyph.*` 负责共享图标尺寸和前景色，`StatusCardIconStyle` 负责状态卡图标。
- 纯图标按钮必须提供 `ToolTip`；相同作用在不同页面使用相同图标和文案。
- 文本输入、密码、下拉、开关和进度条复用 `SoftTextBoxStyle`、`SoftPasswordBoxStyle`、`StandardComboBoxStyle`、`SoftSwitchStyle`、`SoftProgressBarStyle`。
- 颜色只通过语义画刷资源引用，文字遵循 `Typography.xaml` 的层级。
- UI 文案使用中文；协议名、标准名、文件格式和必要字段标识可保留英文。操作文案使用清晰动词。
- 长路径、日志和动态文本使用 `TextTrimming`、换行、滚动或完整内容 `ToolTip`，不得覆盖相邻控件。

### 8.1 路径显示语义

- 路径控件必须按其代表的目标类型决定显示内容，不得因当前选中项或内部实现方式改变显示语义。
- 目标为目录时，正文显示目录路径，不得只显示末级文件夹名称；例如应用数据目录、流程配置目录。
- 目标为文件时，正文只显示文件名，不显示父目录路径；例如 `projects.json`、日志文件和固件文件。
- 无论正文显示目录路径还是文件名，`ToolTip` 均应绑定完整路径，便于用户核对实际位置。
- 路径过长时沿用 `PathDisplayTextStyle` 的省略显示，不得通过压缩为末级名称改变目录字段的语义。
- 操作文案与目标类型保持一致：目录使用“更改目录…”，文件使用“更改文件…”；“打开位置”可统一打开目标所在目录。
- 缺失、无效等状态提示可以附加在正文前，但不得替换或隐藏上述目录路径或文件名。

### 8.2 两类按钮复用

| 分类 | 共享样式 | 典型场景 |
|---|---|---|
| 普通 | `Button.Normal` | 刷新、浏览、导出、重新加载、校验、取消、返回、移动、保存、创建、连接、开始刷写、发送、确认、关闭视图，以及最小化、最大化、还原、关闭等窗口控制 |
| 危险 | `Button.Danger` | 删除、清空、取消刷写、放弃未保存修改；必须配合明确文案，必要时二次确认 |

新增或修改任何按钮时，必须按以下顺序完成分类，不得跳过：

1. 属于窗口最小化、最大化、还原或关闭控制：使用 `Button.Normal`，同组按钮视觉完全一致。
2. 会直接造成数据删除、内容清空、任务中止、连接断开或未保存修改丢失：使用 `Button.Danger`，并判断是否需要二次确认。
3. 其他操作：使用 `Button.Normal`。

同类操作直接引用上述两个样式，不得在页面重新声明配色、背景或状态触发器。连接按钮通过 `Tag` 在 `Button.Normal` 内根据连接状态切换为危险语义；其他图标按钮直接按操作结果选择普通或危险样式。颜色与交互态集中维护在 `Styles/Controls/ButtonStyles.xaml` 及其引用的语义资源中。

窗口控制按钮示例：

```xml
<Button ToolTip="关闭"
        Width="46"
        Height="46"
        Padding="0"
        Margin="0"
        Style="{StaticResource Button.Normal}"
        shell:WindowChrome.IsHitTestVisibleInChrome="True"
        Click="Close_Click">
    <controls:FluentIcon Kind="Close"
                         Style="{StaticResource Button.Glyph}"
                         Foreground="{Binding Foreground, RelativeSource={RelativeSource AncestorType=Button}}" />
</Button>
```

图标与文字应跟随按钮前景色，调用示例：

```xml
<Button Command="{Binding ClearRuntimeConfigurationCommand}"
        Style="{StaticResource Button.Danger}">
    <StackPanel Style="{StaticResource Button.InlineContent}">
        <controls:FluentIcon Kind="DeleteOutline"
                             Style="{StaticResource Button.Glyph.Current}" />
        <TextBlock Text="清空" Style="{StaticResource Button.IconLabel}" />
    </StackPanel>
</Button>
```

## 9. 交互、状态与 MVVM

- 用户操作通过命令绑定进入 ViewModel。同步操作用 `RelayCommand`，异步操作用 `AsyncRelayCommand` 和 `CancellationToken`。
- 不得在 UI 线程执行文件解析、设备通信、刷写或大批量数据处理。
- 代码隐藏只处理拖放、焦点、窗口、滚动和控件专属事件；业务判断、数据修改和流程编排放入 ViewModel/Core。
- 每个页面按实际工作流检查初始、正常、无数据、加载/执行中、禁用、校验失败、操作失败、取消和完成状态。
- 状态列表是适用性检查表，不要求每个页面机械实现全部状态，但不得遗漏适用的失败路径和重复提交防护。
- 命令执行期间保持布局稳定；状态文字、进度值和按钮文案变化不得导致关键控件跳位或遮挡。
- 错误反馈说明发生了什么以及用户可以采取的下一步，不向用户显示无上下文的异常堆栈。

## 10. 可用性与可访问性

- 以 `MainWindow` 的当前最小尺寸为下限检查页面，不得依赖默认启动尺寸才可使用。
- 工具栏和表单在空间不足时通过合理列布局、换行、滚动或省略处理，不允许相互覆盖。
- 数字、CAN ID、地址、进度和状态区域保持稳定宽度，数据变化不应重排整页。
- 可点击区域需要明确的悬停、按下、禁用和键盘焦点状态，优先由共享样式提供。
- 状态和错误不能仅通过颜色传递，应同时使用文字、图标或状态点。
- 交互顺序应符合视觉顺序；对话框和复杂表单应验证 Tab、Shift+Tab、Enter 和 Escape。
- 纯图标操作提供可理解的 `ToolTip`；输入控件必须有邻近标签或可识别的说明。
- 文本缩放、长中文文案和动态路径不得被无提示裁切；必要时提供换行、省略和完整内容提示。
- 不添加纯装饰渐变、光斑、营销式悬浮卡片或与诊断工具场景无关的视觉元素。

## 11. 新页面接入与完成验收

新页面除创建 `Views/<Name>View.xaml` 和代码隐藏外，还必须：

- 在 `MainWindow.xaml` 的 Shell 导航和 `TabControl` 中按同一顺序接入。
- 更新 `MainViewModel.SelectedShellIndex` 相关命令和索引分支。
- 使视图名称、权限和可见性与导航一致；页面顶部不重复显示视图名称，帮助文档入口统一由 Shell「帮助」菜单提供。
- 复用现有 ViewModel 手动装配方式，不引入 DI 容器。
- 将真正可复用的控件或资源放入 `Views/Controls/` 或对应 `Styles/` 分类，并更新本文资源索引。

导航索引是位置契约。插入或删除页面时必须检查所有硬编码索引、命令跳转和上下文文案。

提交可见 UI 改动前逐项确认：

- 已说明页面类型、参考页面、复用资源、关键交互与状态、模板偏离。
- 页面使用标准根骨架和合适的内容模板；仅有必要元信息时保留页头。
- 已检查常规、空数据、忙碌/禁用、错误以及其他适用状态。
- 已检查异步防重入、取消、失败反馈和布局稳定性。
- 已在 `MainWindow` 最小尺寸下确认无裁切、遮挡或文本溢出。
- 已检查键盘焦点、Tab 顺序、Enter/Escape、纯图标提示和非颜色状态表达。
- 已逐项检查新增或修改的按钮：只使用 `Button.Normal` 或 `Button.Danger`；窗口控制按钮属于同组普通操作；危险样式由实际破坏性结果决定，而非文案、图标或位置。
- 新页面已核对导航顺序、Tab 顺序、`SelectedShellIndex` 和上下文文案。
- 已执行 `dotnet build DiagnosticFlashTool.slnx -c Debug`。
- 已尽可能运行应用检查；无法执行的运行时检查在交付说明中明确列出。

仅修改 Markdown 文档且未改动 XAML/C# 时，可以不执行 Debug 构建，但必须完成链接、术语和格式检查。

## 12. 自动检查边界

适合先实施的低误报检查：

- 业务页面新增硬编码十六进制颜色。
- 按钮引用 `Button.Normal`、`Button.Danger` 之外的视觉样式，或页面局部定义按钮配色和交互状态。
- 最小化、最大化、还原和关闭等窗口控制未统一使用 `Button.Normal`，或关闭按钮出现危险红色悬停状态。
- Shell 页面缺少标准根布局、已有页头未引用标准样式，或在页头重复提供帮助文档按钮。
- 长表格/列表将垂直滚动设置为 `Disabled`。
- 新页面未接入 Shell 导航或 `TabControl`，或顺序不一致。
- 文档链接失效、Markdown 尾随空白和重复标题。

以下检查不能只靠简单正则作最终判定：

- 样式、画刷或控件资源是否为死资源。
- `BasedOn`、`StaticResource`、`DynamicResource` 和模板内部依赖是否完整。
- 两个资源是否语义重复、是否应合并。
- 页面状态是否覆盖完整、焦点顺序是否合理、最小窗口是否裁切。

这类问题需要资源依赖图、XAML 解析或运行时人工复核。自动检查结果应作为线索，不直接触发删除或大范围重构。

## 13. 术语

| 术语 | 定义 |
|---|---|
| Shell 页面 | 挂载在 `MainWindow` 导航和主 `TabControl` 中的业务页面 |
| 页面骨架 | 页面根布局、页头、页头间隔和主体区域的标准结构 |
| 公开资源入口 | 业务页面应直接引用的稳定样式或复用控件资源 |
| 内部实现资源 | 仅供复用控件或模板内部使用，不向业务页面推荐的资源 |

## 17 校验结果与执行行（v3.4）

本次在 B 方案基础上补两处信息可视化缺陷：校验结果没有状态语义、刷写执行时表格行不可辨识。两处都只改视图层与展示状态，不改变业务校验规则。

### 17.1 校验结果语义化

- 数据：`MainViewModel.ApplyFlowValidationResult` 把错误/提示转成 `FlowValidationLine`（`Info` / `Warning` / `Error`），同时继续维护 `FlowValidationText` 以兼容既有绑定。
- 视图：`FlowConfigView` 校验结果卡顶部为状态胶囊（语义色底 + 圆点 + 状态文字 `N 项错误` / `N 项提示` / `校验通过` / `尚未校验` + `共 N 个流程节点`），下方为逐条列表（图标 + 语义色 + 等宽文字）。
- 状态底色使用 `Status*SoftBrush` / `Status*BorderBrush`，文字使用 `Status*Brush`；同时保留图标和文字，满足第 10 节"状态不能仅通过颜色传递"。
- 未选择项目、未选择 BOOT、加载异常通过 `SetFlowValidationNotice` 写入单条 `Info` 行，状态显示"尚未校验"，不再把异常文本伪装成校验结果。
- 卡片高度改为 `Auto` + `MaxHeight=220`，列表区 `MaxHeight=150`，异常项较多时在卡内滚动，不挤压表格。

### 17.2 执行行高亮

- `FlashProgress` 增加 `StepId`（非步骤级进度为 `null`），`FlashFlowExecutor` 在每步开始时上报当前节点号。
- `MainViewModel.CurrentExecutingStepId` 与 `FlowStepEditorRow.IsExecuting` 联动；刷写完成、取消、失败均清空。
- 新增全局行样式 `DataGrid.RowRunning`：仅在 `IsExecuting=true` 时应用 3px 左侧主色轨与 `PrimarySoftBrush` 底色，其余行保持原样。页面通过 `ItemContainerStyle` 引用，不在页面内自定义行样式（第 6.2 节）。

### 17.3 验证与限制

- 全解决方案构建通过；校验结果卡运行态截图确认：错误胶囊、红色逐条文本、节点计数与滚动高度均正确。
- 执行行高亮已接通 Core → ViewModel → 行样式，但未做运行态截图验证（需要 Mock 设备跑通一次刷写流程）；`IsExecuting` 默认为 `false`，未执行刷写时表格视觉与之前一致。

### 17.4 项目导航折叠控件

- Fluent 默认的 `Expander` 展开按钮在深色侧栏上会画出一个白色圆底，视觉上像散落的白点，与紧凑导航不协调。
- `ShellProjectExpanderStyle` 因此改为局部 `ControlTemplate`：18px 列内放 12px `FluentIcon`（`ChevronRight` → 展开时 `ChevronDown`），整行 34px 高、透明底、悬停用 `SidebarHoverBrush`，不使用圆形填充。
- 折叠头部的项目名与文件夹图标显式使用 `SidebarTextBrush`：`Typography` 中的隐式 `TextBlock` 样式会覆盖继承前景，仅靠模板继承会回落到深色正文色。
- 该模板只服务 Shell 导航，不改变 Fluent `Expander` 在其他页面的默认外观。

### 18.3 项目详情面板底色

- 项目配置页右侧详情原本是一整张白色 `HeaderedCard`，深色侧栏旁边形成约 32 万像素的纯白块，与页面底色的对比只有 1.13:1，观感是"一整片没有层次的亮斑"。

- 效果：该区域纯白占比从约 90% 降到约 47%，亮感明显下降，同时表单字段因为白底反而更突出。

### 18.4 内容区底色加深（v3.7）

- 面板改为页面底色后，白卡与底色的对比只有 1.12:1，卡片边界几乎只靠边框支撑；把 `Color.App.Background` 从 `#EFF2F4` 加深到 `#E9EDF1`（相对亮度 0.884 → 0.842），白卡/底对比提升到 1.18:1，卡片与输入框在视觉上更明确地"浮起"。
- 这是**全局令牌**，影响 7 个页面的内容区底色；次要文字与底色的对比从 8.9:1 降到 8.5:1，仍远高于 AA 的 4.5:1。
- `SurfaceBrush`（工具栏、停靠页签）与日志面板底色不变，因此工具栏相对内容区略亮、日志面板略亮，层级关系保持不变。
- 若后续仍觉得分层不足，下一档建议 `#E4E9EE`（白卡/底 约 1.28:1），再深就会让浅灰表头和卡片失去区分。

### 18.11 无标题卡片统一帧 ID 上下间距（v4.4）

- 基准：开发者选项「帧 ID」工具条卡片（`Card.Toolbar`）= 1 DIP 边框 + 10 DIP 内边距 + 32 DIP 内容行，总高 54 DIP。此前只有这一张卡片稳定落在该尺寸，其余无标题卡片的行高取决于内容，例如刷写进度卡只有 44 DIP。
- 新增公开资源 `Card.ContentRow`（`Layout/CardStyles.xaml`，`TargetType=FrameworkElement`，`MinHeight=CardContentRowHeight`），作为无标题卡片首行或唯一行的唯一行高入口；页面不再自己写 `MinHeight`。
- 应用位置：开发者选项项目卡与刷写进度卡、固件刷写运行台工具行、操作日志筛选行、流程配置工具行（后者原先把 `MinHeight` 直接写在页面里，现改为引用该样式）。
- 可见变化：开发者选项底部刷写进度卡由 44 DIP 变为 54 DIP，进度条与「开始时间 / 持续时间」在 32 DIP 行内垂直居中；其余位置当前渲染高度不变，属于声明性加固，避免以后换内容时行高漂移。
- 不在范围：带标题卡片（标题行已使用同一 `CardContentRowHeight`）、`DialogPanelStyle` 对话框面板（16 内边距为有意保留）、整块填充的表格卡（算法配置、操作日志列表体），它们仍按 5.1 的 10 DIP 上下留白处理。
- 验证：Debug 构建通过；布局探针逐页实测 7 个页面的无标题卡片，上下留白均为 10.43 / 9.86 DIP（175% DPI 下 1 px 边框取整），单行卡片高度均为 54.29 DIP。
