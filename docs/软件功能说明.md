## 1. 文档目的

本文档统一说明 DiagnosticFlashTool 当前可交付的软件功能、业务规则、数据边界、已知限制和最低验收要求，用于：

- 研发确认功能职责、输入输出及实现边界。
- 测试设计功能、异常、回归和台架测试用例。
- 产品及需求方判断功能是否达到当前验收基线。

当界面文案、历史设计稿或口头描述与本文档不一致时，应先结合当前代码和配置确认差异，再决定修订需求、实现或本文档，不应默认把未接通的界面元素视为已完成功能。

## 2. 范围与产品形态

### 2.1 通用主程序

`DiagnosticFlashTool.App` 是通用 BOOT 刷写与配置管理程序，提供项目配置、BOOT 流程配置、CAN 设备连接、刷写执行、CAN 报文监控、日志和系统设置等功能。

### 2.2 ECU 专用工具

`DiagnosticFlashTool.Product.EcuX` 是面向固定 ECU 的独立产品壳。它复用通用协议和刷写能力，以产品配置约束通信参数、流程和固件槽位，并提供 Seed&Key DLL、UDS 时间参数、多应用镜像、刷写取消和步骤状态功能。

### 2.3 共享组件

| 组件 | 职责 |
| --- | --- |
| `DiagnosticFlashTool.Core` | CAN 抽象、ISO-TP、UDS、固件解析、Seed&Key 注册表和刷写流程执行 |
| `DiagnosticFlashTool.Infrastructure` | JSON 配置仓储、Mock/ZLG CAN 设备和外部 Seed&Key DLL 适配 |
| `DiagnosticFlashTool.Application` | 组织专用工具的一次完整连接及刷写会话 |
| `DiagnosticFlashTool.SeedKeyWorker` | 在独立 x86 进程中调用供应商 Seed&Key DLL |

### 2.4 系统边界

当前基线仅支持 Windows 桌面环境、经典 CAN 和基于经典 CAN 的 ISO-TP/UDS。以下能力不属于当前已实现范围：

- CAN FD、LIN、以太网诊断或 DoIP。
- 用户账号、服务端认证及多角色授权。
- 云端配置、数据库服务或远程任务下发。
- 刷写历史持久化和历史报表。
- 已接入真实采集源的配方功能检测。

## 3. 功能状态定义

| 状态 | 判定规则 |
| --- | --- |
| 已实现 | 当前存在可访问入口和完整业务行为，可按本文档验收 |
| 部分实现 | 已有界面或部分逻辑，但存在明确未接通能力；只能验收本文档列出的已实现部分 |
| 未实现 | 仅有占位界面、数据模型或说明，不得计入需求完成率 |
| 条件实现 | 软件能力已具备，但必须依赖指定硬件、DLL、配置或运行时才能验收 |

功能验收必须同时检查正常路径、失败反馈和持久化结果。仅看到页面、按钮或配置字段不代表对应业务已实现。

## 4. 用户与权限

当前主程序只有本机交互用户，不区分操作员、工程师和管理员权限。所有导航页面和业务命令默认对用户开放。

管理员模式已实现密码校验和当前进程内的状态展示，但管理员状态尚未绑定页面、字段或命令权限，因此不能作为业务授权或安全边界。详细规则见 [管理员模式功能说明](管理员模式功能说明.md)。

### 6.6 通用刷写流程

通用主程序当前从“开发者选项”页面启动刷写。“固件刷写”页面用于设备连接和状态查看，不是当前的刷写启动入口。

启动按钮满足以下条件时可用：CAN 已连接、已选择项目、当前没有其他异步操作。执行流程为：

1. 清零总进度并把状态切换为刷写中。
2. 优先使用当前选中的 BOOT 配置；没有当前选择时使用项目绑定的 BOOT 配置。
3. 从当前运行路径或项目路径加载 Driver 和 Application 固件。
4. 使用项目中的物理请求、功能请求和响应 CAN ID 创建 ISO-TP/UDS 会话。
5. 按 BOOT `flow` 顺序逐项执行普通 UDS、Driver 下载或 Application 下载节点。
6. 所有节点成功后进度更新为 100%，状态显示完成；任一步骤异常则停止后续步骤并记录失败原因。

| 功能编号 | 状态 | 功能及验收准则 |
| --- | --- | --- |
| FLS-001 | 已实现 | 流程节点严格按 `flow` 顺序执行，每个节点开始和完成时更新日志及总进度 |
| FLS-002 | 已实现 | 普通节点由 `service + subService + extend` 组成请求；寻址值为 `functional` 时使用功能请求 ID，其余使用物理请求 ID |
| FLS-003 | 已实现 | 安全访问 0x27 奇数子功能保存 Seed；偶数子功能在发送前调用注册算法计算 Key；Key 请求早于 Seed 时失败 |
| FLS-004 | 已实现 | 下载节点依次执行 RequestDownload 0x34、TransferData 0x36 和 RequestTransferExit 0x37，并对固件的每个地址块分别下载 |
| FLS-005 | 已实现 | 传输块数据长度受节点 `blockSize`、ECU 返回最大块长度和 ISO-TP 上限共同约束；块计数从 1 开始并循环 |
| FLS-006 | 已实现 | UDS 否定响应、响应 SID 不匹配、响应为空、超时、ISO-TP 序号错误或文件解析错误均导致当前刷写失败 |
| FLS-007 | 部分实现 | 通用主程序没有对刷写操作提供用户可见的取消按钮，当前 UI 发起的刷写不能主动取消 |
| FLS-008 | 部分实现 | 通用主程序直接使用 Core 执行器，未启用 `DiagnosticFlashTool.Application` 中的周期 Tester Present 调度 |

## 7. ECU-X 专用工具功能

### 7.5 专用流程限制

专用会话在开始刷写前拒绝包含 `eraseRoutine`、`crcAlgorithm`、`receive` 或 `verify` 元数据的节点，因为这些元数据尚未实现。需要擦除、校验或 CRC 时，应先在 BOOT 配置中定义当前执行器能够处理的显式 UDS 例程步骤，并完成目标 ECU 验证。

产品配置中的 CAN 地址、帧格式、波特率和 BIN 回退地址当前为示例值，未根据目标 ECU 通信矩阵确认前，ECU-X 只能按开发或 Mock 基线验收，不能按量产实车能力验收。

## 8. 共享协议规则

### 8.1 ISO-TP

- 单帧有效负载不超过 7 字节时使用单帧发送。
- 多帧发送支持首帧、流控帧和连续帧，经典 CAN ISO-TP 有效负载上限为 4095 字节。
- 多帧接收校验连续帧序号，接收目标只接受配置的响应 CAN ID。
- 响应多帧时，工具发送流控帧并使用配置的 Block Size 和 STmin。
- 发送多帧请求时等待 ECU 流控帧；等待超时则当前请求失败。

### 8.2 UDS

- 同一 `UdsClient` 的诊断请求串行执行。
- 肯定响应 SID 必须等于请求 SID 加 `0x40`。
- 否定响应记录 SID 和 NRC 并作为失败返回，NRC `0x78` 除外。
- NRC `0x78` 表示 Response Pending，继续等待最终响应，直至收到非 Pending 响应、取消或超过总超时。
- 普通节点可按物理寻址或功能寻址发送，响应仍从配置的响应 ID 接收。

### 8.3 安全访问

通用内置算法注册名为 `AES128_OneFunc`，算法名称匹配不区分大小写。该实现要求 Seed 长度为 16 字节的非零整数倍。产品专用算法可通过注册表接入外部 DLL。

### 8.4 下载

- RequestDownload 使用 4 字节地址和 4 字节长度。
- 每个固件地址块分别建立下载、传输数据和退出传输过程。
- ECU 返回最大块长度时，以 ECU 能力限制 TransferData 数据量。
- 任意服务的空响应、否定响应、SID 不匹配或超时都会终止当前流程。

## 11. 最低验收基线

### 11.1 构建与自动化验证

```powershell
dotnet build DiagnosticFlashTool.slnx -c Debug
dotnet test DiagnosticFlashTool.slnx -c Debug
```

构建及现有自动化测试必须通过。协议、刷写、固件解析或配置保存发生修改时，应补充与风险对应的自动化测试，不能只以界面启动成功作为回归结论。

| 编号 | 当前限制 | 对验收的影响 |

## 14. 文档维护规则

发生以下变化时必须同步修订本文档及受影响的测试用例：

- 新增、删除或调整导航页面和可访问入口。
- 修改项目、BOOT、产品配置或本机设置的数据结构及保存规则。
- 修改 CAN、ISO-TP、UDS、Seed&Key、固件解析或下载协议行为。

- 增加新硬件、总线类型、固件格式或 ECU 产品变体。

每次发布验收应记录使用的代码版本、配置版本、硬件/驱动版本、测试环境、未关闭限制和最终结论，避免只用本文档日期代替实际版本基线。
