## 0. 执行结论

原建议的主要方向成立：原文混合了稳定规则与易腐实现快照，且部分页面、尺寸、样式变体和术语已经漂移。修订时应删除易腐快照、保留稳定规则，并补齐可判定的语义口径。

但不得按原建议原样执行。原稿存在变体数量计算错误、把 `.Actions` 等同于“存在操作区”、把不同层级的间距资源误判为重复入口、间距刻度未完成盘点以及自动检查判据过于理想化等问题。

本次建议采用以下原则：

| 原则 | 执行口径 |
|---|---|
| 职责清晰 | 正式规范使用 `docs/界面设计规范.md`，并同步更新仓库内全部引用 |
| 删除易腐快照 | 页面尺寸、引用次数和文件清单不进入长期规范，需要时从当前源码即时核对 |
| 分层事实来源 | 流程和语义以规范为准；精确数值、页面现状和引用关系以当前源码为准 |
| 先纠错后重构 | 先修正文档事实与术语；样式删除、重命名、变体压缩和令牌体系调整另行评审 |
| 可验证优先 | 自动检查先覆盖低误报项目；资源图解析、死资源判定等复杂检查逐步引入 |

## 1. 基线与变更边界

### 1.1 必须先冻结核对基线

当前工作区同时修改了目标规范、`HeaderedCard`、卡片样式和多个页面。正式修订和验证时应在交付记录中说明：

- 核对日期；
- 对应 Git 提交；
- 是否包含未提交改动；
- 扫描文件范围与排除项；
- 核对方式和未完成的运行时检查。

没有提交号的“当前源码实测”只能作为临时工作区结论，不应写入稳定规范成为长期事实。

- `docs/软件功能说明.md`；
- `docs/改造建议与功能缺口分析.md`；

### 1.3 规范头部元数据

稳定规范建议包含：


## 2. 事实来源与存量偏差

原文使用单一优先级链条处理规则、数值和实现快照，容易造成“正文引用附录、附录又低于源码”的环路。建议改成分层职责：

| 信息类型 | 权威来源 |
|---|---|
| 用户当前任务的明确要求 | 用户要求 |
| 页面模板、交互语义、资源准入与验收流程 | 稳定规范 |
| 颜色、尺寸、间距、圆角、控件默认值 | 当前资源字典和复用控件源码 |
| 页面数量、样式引用次数、具体页面尺寸 | 当前源码和本次任务的临时核对结果 |

正文中的“当前尺寸见附录”应改为指向对应资源字典；实现统计不进入稳定规范，也不参与定义规则。

规范还应增加存量偏差规则：

> 现有页面中与规范不一致的显式覆盖属于存量偏差。若本次修改触及该区域，应就地评估并修正；未触及的偏差登记为后续任务，不自动扩大本次交付范围，也不得复制到新页面。

## 3. `HeaderedCard` 的正确口径

### 3.1 当前键集合

当前资源字典共定义 13 个 `HeaderedCard.*` 样式键，其中 1 个基础样式、12 个可选业务变体：

```text
HeaderedCard.Base
HeaderedCard.Form
HeaderedCard.Form.Lead
HeaderedCard.Form.Actions
HeaderedCard.Form.Actions.Lead
HeaderedCard.Panel
HeaderedCard.Panel.Lead
HeaderedCard.Panel.Centered
HeaderedCard.Panel.Centered.Lead
HeaderedCard.Data
HeaderedCard.Data.Lead
HeaderedCard.Data.Actions
HeaderedCard.Data.Actions.Lead
```

因此不得继续使用“13 个变体”或“合法组合共 10 个”这类含混计数。建议明确写成“13 个键，其中 12 个业务变体”。

### 3.2 `Actions` 属性与 `.Actions` 样式不是同一概念

- `HeaderedCard.Actions` 是控件属性，用来承载标题栏右侧内容；
- `.Actions` 是样式名后缀，只表达“标题栏含多个工具栏按钮”的语义，标题栏高度与标准一致（44）；
- 有操作区不必然使用 `.Actions` 样式。项目编辑卡只有一个关闭图标，仍使用标准的 `HeaderedCard.Form`；
- 当前规范约定为：包含两个及以上 32 高操作按钮时使用 `.Actions` 变体；单个能在标准标题栏中稳定显示的图标按钮可保留基础变体。

建议正文采用以下表述：

> 标题操作通过 `HeaderedCard.Actions` 属性提供。多个工具栏按钮使用带 `.Actions` 后缀的样式，但该后缀不改变标题栏高度；标题按 `HeaderedCardHeaderTopInset` 距卡片顶部固定定位，页面不得自行硬编码标题栏高度或标题偏移。

### 3.3 当前使用统计

当前工作区中 `<controls:HeaderedCard.Actions>` 共出现 5 处，分布在 4 个业务页面：

- `ProjectConfigView.xaml`：2 处；
- `FlowConfigView.xaml`：1 处；
- `DeveloperOptionsView.xaml`：1 处；
- `SystemSettingsView.xaml`：1 处。

当前被页面直接使用的新增高标题栏样式为：

- `HeaderedCard.Data.Actions`：3 个页面；
- `HeaderedCard.Form.Actions.Lead`：1 个页面。

`HeaderedCard.Form.Actions`、`HeaderedCard.Data.Actions.Lead` 当前虽已定义，但没有页面直接引用。临时核对结果应区分“已定义”和“已使用”，不能混写。

### 3.4 不建议立即压缩变体

把 `.Lead` 和 `.Actions` 全部改成页面显式属性会减少样式数，但会增加页面 XAML 重复并削弱“选中样式即满足布局约束”的效果。此方案属于资源架构重构，不属于文档纠错，应单独比较迁移成本、可读性和误用风险后再决定。

## 4. 间距入口与资源治理

### 4.1 不把不同层级误判为重复入口

以下资源虽然都涉及卡片间距，但职责不同：

| 资源 | 层级与职责 |
|---|---|
| `PageCardBottomGap` | 底层间距令牌，可被样式复用 |
| `HeaderedCard.*.Lead` | `HeaderedCard` 的语义变体，内部引用底层令牌 |
| `PageLeadStandardCardStyle` | 无标题 `Border` 卡片的页面级样式 |

因此不能以“同一需求有三个官方入口”为由直接二选一。正确做法是明确各自适用的目标类型，并检查页面是否实际使用。

当前 `PageLeadStandardCardStyle`、`PageTrailingStandardCardStyle`、`PageTrailingCompactCardStyle`、`PageSummaryCardStyle` 和 `PageSummaryContentStyle` 均没有业务页面直接引用。建议先标记为“候选死资源”，确认不存在动态引用或后续模板依赖后，再在独立清理提交中删除。

### 4.2 三类底部空间应明确职责

| 资源 | 职责 |
|---|---|
| `HeaderedCardBodyPadding` 下侧值 | 卡片边框内部的内容留白 |
| `PageCardBottomGap` / `.Lead` | 卡片与下一页面区块之间的外部间距 |
| `PageContentBottomGap` | 页面主体内容与可用内容区底边之间的收尾空间 |

### 4.3 间距刻度需要先盘点

暂不直接写入“只允许 0、4、8、12、16、24、32”。当前样式和页面还使用 5、6、10、14、18、20、28 等多种值，其中部分是图标间距、按钮内边距、固定控件尺寸或局部布局值。

正确顺序是：

1. 扫描所有共享样式与业务页面中的尺寸值；
2. 区分版式间距、控件内边距、固定尺寸和兼容性覆盖；
3. 统计重复频率和语义；
4. 再决定基础刻度及允许的例外值；
5. 最后编写可自动验证的规则。

## 5. 模板、状态与资源映射

### 5.1 页面类型应作为模板目录，不作为封闭枚举

`§3.2` 的模板表适合充当“参考模式目录”，但不应声明为互斥且封闭的 9 类。新增独立模态窗口后，模板数量本身还会变化。

建议 `§2` 改为：

> 从 §3.2 选择与当前工作流最接近的模板；若页面同时包含多个模式，可组合现有骨架和资源，并说明主要参考页面。

模板表应补充：

| 模板 | 参考实现 | 核心约束 |
|---|---|---|
| 独立模态窗口 | `Views/UnsavedChangesDialog.xaml` | 无系统标题栏、居中、明确确认/取消/危险路径和关闭行为 |

### 5.2 状态清单是适用性检查表

`初始、正常、无数据、加载/执行中、禁用、校验失败、操作失败、取消、完成` 应定义为适用性检查表，而不是要求每个页面机械实现全部状态。

设计说明只需列出本页适用状态，但必须覆盖：

- 命令失败；
- 重复提交防护；
- 长时间操作的忙碌或进度反馈；
- 存在数据容器时的空数据表现。

### 5.3 增加语义到资源映射

建议新增规范性映射表，至少覆盖：

| 语义 | 首选资源 |
|---|---|
| 普通操作 | `Button.Normal` 或隐式默认按钮样式 |
| 主操作 | `Button.Primary` |
| 危险操作 | `Button.Danger` |
| 工具栏操作 | `Button.ToolBar` |
| 纯图标操作 | `Button.Icon`，必须提供 `ToolTip` |
| 路径操作 | `Button.PathAction` + `PathDisplayBorderStyle` |
| 对话框确认/取消 | `Button.DialogPrimary` / `Button.DialogSecondary` |
| 设备连接 | `Button.ConnectionAction` / `Button.ConnectionPrimaryAction`，仅限对应业务场景 |
| 页头帮助 | `Button.HelpDocument` 或 `PageHelpDocumentButton.Standard` |
| 带标题表单 | `HeaderedCard.Form` 系列 |
| 带标题数据列表 | `HeaderedCard.Data` 系列 |
| 状态、日志和诊断面板 | `HeaderedCard.Panel` 系列 |

映射表表达“首选资源和适用场景”，不要承诺每种语义永远只有一个样式键。

### 5.4 增加可访问性与术语表

建议在“布局与可用性”后增加可访问性小节，至少覆盖焦点顺序、键盘可达性、Enter/Escape、焦点恢复、非颜色状态表达和纯图标按钮说明。

术语表至少定义：卡片、面板、区块、页头、操作区、Shell 内遮罩、独立模态窗口、主体内容层。

## 6. 资源准入与命名

### 6.1 资源准入

新增共享颜色、间距、圆角或控件样式前应满足：

1. 现有资源不能准确表达所需语义；
2. 名称优先表达角色和使用场景，而不是颜色外观；
3. 有明确的共享价值，或属于必须集中维护的基础令牌；
4. 放入职责最接近的资源字典，并补充语义映射或说明；
5. 单页业务布局优先保留在页面资源中。

“至少两个位置复用”可以作为判断共享价值的经验规则，但不应作为绝对准入条件。基础主题令牌、控件契约或预期近期复用的资源可能只有一个当前引用。

### 6.2 命名统一属于独立迁移

`PageSummaryRowStyle`、`Card.Compact`、`CardStyle` 等命名确实混用后缀式和点分层级，但全量重命名会影响大量 `StaticResource` 引用。

建议先规定新增资源采用哪一种命名方式；现有资源在实际触及或专门迁移时逐步统一，不在文档纠错批次中一次性改名。

## 7. 自动化校验

### 7.1 第一阶段：低误报检查

可以优先实现：

- `Views/**/*.xaml` 中直接出现十六进制颜色；
- Shell 导航、主 `TabControl` 和实际页面文件集合不一致；
- 规范登记的 `HeaderedCard` 键集合与资源字典不一致；
- 业务页面是否误用 `VerticalScrollBarVisibility="Disabled"` 代替 `Hidden`；
- `dotnet build DiagnosticFlashTool.slnx -c Debug` 是否通过。

### 7.2 第二阶段：需要资源图解析的检查

以下项目不能只用简单正则直接判失败：

- `StaticResource` 是否定义：资源可能来自页面资源、合并字典、隐式样式或第三方主题；
- 死资源：零直接引用不等于无动态引用、`BasedOn` 引用或模板间接引用；
- 命名规则：需要区分样式、画刷、尺寸令牌、隐式资源和兼容别名。

这些检查应解析 `AppStyles.xaml` 的合并关系和资源依赖图。无法可靠解析前，只输出非阻断诊断，不自动删除资源，也不阻断构建。

## 9. 建议实施顺序

| 批次 | 内容 | 是否改代码 | 验收 |

| P0-1 | 冻结提交基线，修正幽灵页面、页面清单、尺寸和引用统计 | 否 | 每条统计可定位到源码或 Git 记录 |

## 10. 完成标准

修订完成后应满足：

- 规范文件有稳定入口、版本和生效信息；
- 规范正文不引用易腐的附录数字作为强制规则；
- `HeaderedCard.Actions` 属性与 `.Actions` 样式不再混称；
- 规范和正式文档不再包含 `FlashMonitorView` 幽灵页面统计；
- `UnsavedChangesDialog` 已纳入模板和交互规则；
- 所有仓库内文档链接仍有效；
- 文档批次没有擅自删除或重命名样式资源；
- 若后续修改 XAML 或资源，按 UI 规范完成最小窗口、常规、空数据、忙碌/禁用、错误状态检查，并执行 Debug 构建。

本修订版作为实施依据；原稿中与本版冲突的变体数量、`.Actions` 维度、间距入口、刻度值和自动检查判据不再采用。
