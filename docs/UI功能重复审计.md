# UI 功能重复设计审计

- 审计日期：2026-11-10
- 对照文档：`docs/软件功能说明.md`（功能地图与编号）、`docs/改造建议与功能缺口分析.md`（DSG/APP/FLW/LOG 条目）、`docs/界面设计规范.md`（页面模板）
- 对照代码：`src/DiagnosticFlashTool.App/Views/*.xaml`、`MainWindow.xaml`、`Styles/**`
> **处理状态（2026-11-10 更新）**：R3「连接/断开」已收口——工具栏改为只读连接状态，连接操作只在固件刷写页与刷写菜单；R4「日志」已收口——完整日志功能替换原历史记录入口，底部日志面板仅显示操作输出，校验结果只在流程配置页展示；R6「节点编辑」已处理——节点操作从全局菜单移除，只保留在流程页工具行；R2「流程文件打开/保存/校验」已收口——工具栏不再提供三项，仅保留文件/刷写菜单与页内工具行。

- 结论口径：**同一能力在两个及以上界面位置出现，且用户无法从位置区分用途**，才算重复；仅"同一数据在不同粒度展示"（如标题栏显示项目名、项目配置页编辑项目）不计入。

## 0. 结论摘要

1. 现存重复共 **7 簇**，其中 **4 簇是 2026-11-10 桌面 Shell 改版引入或放大的**（工具栏 + 菜单栏与页内工具行三处并存）。
2. 文档中记录的 `DSG-002「三页职责重叠 / 报文表两份」` 已随"刷写监控"页删除而**实际消解**，但文档仍在描述它 —— 属文档滞后，不是现存重复。
3. 最该先处理的是 **刷写启动入口 4 处**（源文档 `DSG-001` 已点出"主入口位置不合理"，改版后变成"两页都能启动"）与 **流程文件 打开/保存/校验 各 3 处**。

## 1. 重复簇清单

### R1 刷写控制：4 个入口（最严重）

| 位置 | 证据 |
|---|---|
| Shell 工具栏「开始刷写 / 停止」 | `MainWindow.xaml` 工具栏，`StartFlashCommand`、`CancelFlashCommand` |
| Shell 菜单「刷写 → 开始刷写 / 停止刷写」 | `MainWindow.xaml` 菜单栏 |
| 固件刷写页运行台「开始刷写 / 停止」 | `Views/FirmwareFlashView.xaml`，同名命令 |
| 开发者选项页「开始刷写 / 取消」 | `Views/DeveloperOptionsView.xaml`，同名命令 |

- 文档依据：`DSG-001`（刷写主入口位于"开发者选项"，首页无开始按钮）、`软件功能说明 6.6`（"通用主程序当前从开发者选项页面启动刷写；固件刷写页用于设备连接与状态查看"）。
- 现状偏差：文档描述的"单入口"已不成立，现在是**双页 + 双 shell 入口**，且两页的按钮文案不一致（停止 / 取消）。
- 风险：操作员无法判断哪个才是权威入口；两个入口的可用条件若不一致（CanExecute 依赖同一命令，但页面上下文不同）会出现"这里能点、那里不能点"。
- 建议：保留 1 个权威入口（固件刷写页运行台），开发者选项页改为"跳转到固件刷写"；菜单保留但标注仅镜像主入口；工具栏二选一。同步修正 `DSG-001` 与 `6.6`。

### R2 流程文件 打开 / 保存 / 校验：各 3 处（✅ 已处理 2026-11-10，收敛为 2 处：菜单 + 页内）

| 能力 | 位置 |
|---|---|
| 重新加载 | Shell 工具栏「打开」、文件菜单「重新加载配置」、流程配置页「重新加载」 |
| 保存 | Shell 工具栏「保存」、文件菜单「保存配置」、流程配置页「保存」 |
| 校验 | Shell 工具栏「校验 F5」、编辑菜单「校验流程」、流程配置页「校验」 |

- 文档依据：`FLW-001`（选择文件后加载并立即校验）、`FLW-005`（保存与开始刷写前均校验）。
- 风险：三处入口的**可用性语义不一致**——Shell 入口在任何页面都可点，而它们只对"当前流程"生效；用户在固件刷写页点"保存"会保存看不见的数据。
- 建议：Shell 工具栏按当前页面上下文显示（`SelectedShellIndex==4` 才显示这三项），或直接把这三项从工具栏移除，仅保留菜单作为"全局快捷方式"并在菜单项里加页面提示。

### R3 连接/断开 CAN：3 处（✅ 已处理 2026-11-10，收敛为 2 处：页内 + 菜单）

| 位置 | 证据 |
|---|---|
| Shell 工具栏「连接设备」 | `ToggleConnectionCommand` |
| 刷写菜单「连接设备」 | 同上 |
| 固件刷写页运行台「连接设备 / 断开设备」 | 同上，文案随状态变化 |

- 文档依据：`CAN-002`（固件刷写页连接按钮随状态连接/断开）。
- 风险：低（同一命令、同一状态），但状态文案不同步时（`ConnectionActionText` 只在页内使用）会出现"工具栏写连接设备、页内写断开设备"。
- 建议：保留页内为主，工具栏改为**只读状态指示**（如"未连接"文本 + 点击进固件刷写页），或工具栏与页内复用同一文案绑定。

### R4 日志：完整视图重复（✅ 已处理 2026-11-10：操作日志页管理，底部仅显示输出）

| 位置 | 内容 |
|---|---|
| 原历史记录位置的「操作日志」页 | 唯一完整视图 `SystemLogView`，绑定 `FilteredLogEntries`，含级别/关键词/时间筛选、导出、清空、打开文件、自动滚动、日志状态和设置入口 |
| Shell 底部「日志」面板 | `RuntimeLogView` 仅显示未筛选的 `LogEntries` 并自动滚动，不提供筛选和管理工具 |
| Shell 状态栏 | `LatestLogText` + `LogEntryCountText` + 「查看」 |
| 刷写菜单「清空日志 / 导出日志」 | 与操作日志页同名命令，是同一功能的菜单入口 |
| 帮助菜单「打开日志目录」/ 系统设置「打开位置」 | `OpenLogDirectoryCommand` 两处 |

- 文档依据：`LOG-002`（内存日志 1000 条、状态栏最新 1 条，内容由操作日志页和底部面板显示）、`APP-003`（状态栏摘要与展开日志面板）、`LOG-004`（导出只含筛选结果）。
- 处理结果：完整日志管理替换原历史记录占位页，底部仅显示实时操作输出；两处共用 `LogEntryList`，底部不受完整页筛选影响。开发者选项页已删除进度条下方的重复日志区域及其最近 30 条摘要逻辑。状态栏 1 行摘要属于不同粒度展示。原「问题」模块已替换，`FlowValidationText` 只在流程配置页的校验结果区域显示。

### R5 项目/BOOT 配置选择：双份真相

| 位置 | 作用 |
|---|---|
| 项目配置页 → 编辑项目 → `ProjectEditor.BootConfigFile` | 项目级绑定 BOOT 配置 |
| 流程配置页顶部「配置文件」下拉 | 当前会话临时选择 BOOT 配置 |

- 文档依据：`软件功能说明 6.6` 第 3 条："**优先使用当前选中的 BOOT 配置；没有当前选择时使用项目绑定的 BOOT 配置**"——文档已把双来源写成规则。
- 风险：同一份流程"当前选中"与"项目绑定"不一致时，刷写用哪个取决于临时状态；标题栏只显示 `StatusBarProjectText`（项目 + BOOT 文件名），看不出是临时选择还是项目绑定。
- 建议：二选一。要么流程页选择即写回项目（明确提示已修改项目绑定），要么流程页只读展示项目绑定并在标题栏标注"临时"。当前状态最需要的是**同一个值只在一个地方可改**。

### R6 节点编辑操作：菜单与页内工具行各一份（✅ 已处理 2026-11-10）

| 位置 | 命令 |
|---|---|
| 编辑菜单 | 添加 / 更换模板 / 删除 / 上移 / 下移 / 校验 |
| 流程配置页工具行 | 同 6 个命令 |

- 文档依据：`FLW-004`（新增/更换节点走 Shell 级模态弹窗）、`界面设计规范 6.2`（"表格操作放在卡片标题行或紧邻表格的工具栏"）。
- 风险：菜单位于全局，在非流程页也能触发（对不可见数据编辑）；与 `FLW-004` 的"切换页面时自动关闭弹窗"配合会产生"弹窗刚开就被切页关掉"的边界情况。
- 建议：菜单项按 `SelectedShellIndex` 禁用（`IsEnabled` 绑页面），或删除菜单中的节点操作，仅保留页面工具行（符合规范 6.2）。

### R7 设备参数：编辑处与展示处信息不同步

| 位置 | 内容 |
|---|---|
| 系统设置 → CAN 适配器设置 | 设备类型 / 通道 / 波特率 / BDR / 自动搜索（可编辑） |
| 固件刷写页 2×2 摘要 | 设备类型 / 波特率 / 协议 / 波特率模式（只读） |
| Shell 工具栏右侧 | `BaudRateStatusText`（只读） |

- 文档依据：`CAN-001`、`CAN-008`（"自动搜索波特率"字段存在但无入口/无逻辑）、`SET-001`。
- 判断：展示型重复可接受，但三处的**取值口径不一致**（设置页显示配置值，工具栏显示 `SelectedBaudRateMode` 组合文案，页内显示 `BaudRateStatusText`）。
- 建议：统一由 ViewModel 暴露一个 `DeviceSummaryText`，三处复用；顺带处理 `CAN-008` 的"待自动搜索"死文案（`DSG-007`）。

## 3. 建议处理顺序（低成本 → 高收益）

| 顺序 | 动作 | 影响面 | 预期收益 |
|---|---|---|---|
| 1 | 节点操作从「编辑」菜单移除（或按页面禁用） | `MainWindow.xaml` 一处 | 消除"在别的页面编辑不可见数据"的隐患 |
| 2 | 流程文件三项（打开/保存/校验）从工具栏移除，仅留菜单 + 页内 | `MainWindow.xaml` 一处 | 同时解决"全局按钮只对单页有效"的语义错误 |
| 3 | 刷写入口收敛为一处（固件刷写页），开发者选项页改为跳转 | 2 个 View + 1 个命令 | 对齐 `DSG-001`，去掉最大的入口歧义 |
| 4 | ✅ 完整日志替换历史记录，底部仅操作输出；校验结果归流程配置页 | `MainWindow.xaml`、`SystemLogView.xaml`、`RuntimeLogView.xaml`、`FlowConfigView.xaml` | 保留唯一完整日志管理视图 |
| 5 | BOOT 配置选择改为单一来源（项目绑定），流程页只读 | ViewModel + 2 个 View | 消除双份真相 |
| 6 | 统一设备摘要文案，清理"待自动搜索"死文案 | ViewModel | 顺带修 `DSG-007` |
| 7 | 同步文档：页面数、DSG-001/002 状态 | `docs/*.md` | 防止下次审计再次误判 |
